# План за изпълнение

Работата е разделена на етапи; всеки завършва с нещо, което може да се пусне и провери.

## Етап 0 — скеле на монорепото
- `fan-pdm/` с `firmware/`, `backend/`, `ml/`, `LICENSE` (MIT), `.gitignore`, `.editorconfig`.
- GitHub Actions: `pio run` (компилация), `ruff` + `pytest` за `ml/`, `docker compose config` за `backend/`.

## Етап 1 — firmware/ (ESP32 + MPU6050)

### Хардуер
| Сигнал | ESP32 | MPU6050 |
|---|---|---|
| Захранване | 3V3 | VCC |
| Маса | GND | GND |
| I²C данни | GPIO 21 | SDA |
| I²C такт | GPIO 22 | SCL |
| Прекъсване (по избор) | GPIO 19 | INT |

Сензорът се залепва твърдо (цианакрилат/двойно тиксо) за корпуса на вентилатора,
с една ос радиално към ротора.

### Сигнална обработка
| Параметър | Стойност | Защо |
|---|---|---|
| Честота на дискретизация | 1000 Hz (FIFO, `SMPLRT_DIV=0`, DLPF 188 Hz) | USB вентилатор е ~1500–3000 об/мин → 25–50 Hz; виждаме до 4–8-а хармоника |
| Обхват | ±2 g | най-добра резолюция при малки вибрации |
| Прозорец | 1 s = 1000 отчета, без припокриване | по задание; 1 съобщение/s |
| Премахване на DC | изваждане на средното за прозореца | гравитация и отместване |
| RMS, пик, crest | по оси x, y, z | класически индикатори за дисбаланс/удари |
| FFT | Welch: 512 точки, Hann, 50 % припокриване (3 сегмента) | ~1,95 Hz резолюция, по-малко шум от единичен FFT |
| Ленти | 0–10, 10–30, 30–60, 60–120, 120–250, 250–500 Hz (конфигурируеми) | 1× оборот, хармоници, лагери/шум |
| Ос за FFT | векторна сума x+y без DC (конфигурируемо) | радиални вибрации |
| `f_dom` | честота на най-високия пик > 10 Hz | приблизителни обороти |

### Архитектура на кода
- Задача 1 (ядро 1): чете FIFO по I²C 400 kHz, пълни двоен буфер.
- Задача 2 (ядро 0): изчислява признаците върху пълния буфер, сериализира JSON и публикува.
- Wi-Fi/MQTT с автоматично повторно свързване; `seq` брояч за откриване на изпуснати прозорци; LWT съобщение `pdm/<id>/status` = `offline`.
- Време: NTP, `ts` в ms (UTC).
- Конфигурация: `include/secrets.h` (извън git) + `include/config.h`.
- Тестове: `pio test -e native` за функциите за признаци (синусоида с известна амплитуда/честота → очакван RMS и лента).

## Етап 2 — backend/ (docker compose)
| Услуга | Образ | Роля |
|---|---|---|
| mosquitto | `eclipse-mosquitto:2` | брокер, порт 1883; потребител/парола |
| telegraf | `telegraf:1.x` | абонира се за `pdm/+/features`, разплесква JSON към InfluxDB |
| influxdb | `influxdb:2.7` | bucket `pdm`, retention 30 дни; автоматичен setup от `.env` |
| grafana | `grafana/grafana-oss` | провизиран datasource + табло (RMS, ленти като heatmap, anomaly score, аларми) |

Всичко се провизира от файлове (без ръчни кликове); тайните — само в `.env`.
Проверка: `mosquitto_pub` с примерен JSON → вижда се в Grafana.

## Етап 3 — ml/ (Python пакет `fanpdm`)
| Команда | Какво прави |
|---|---|
| `record --label normal\|fault_<вид> --minutes N` | абонира се по MQTT, записва признаците в Parquet (+ метаданни: етикет, условия) |
| `train --data ...` | само нормални данни → `StandardScaler` + `IsolationForest`; праг = 99,5-и персентил на скоровете върху отделена валидационна част от нормалните данни (не разчитаме на `contamination`); записва `model.joblib` + `model.json` (праг, признаци, версия) |
| `evaluate --data ...` | процент фалшиви аларми върху нормални данни и откриваемост върху записи с повреди (ако има) |
| `detect` | оценява всеки прозорец на живо; пише `anomaly_score` в InfluxDB; аларма при **k от n** аномални прозореца (по подразбиране 5 от 10) с хистерезис за изчистване |

Аларми: MQTT `pdm/<id>/alarm` (JSON: ниво, score, кои признаци са най-отклонени) + измерване `alarms` в InfluxDB → анотации в Grafana. По избор: webhook (напр. самостоятелно хостван ntfy).
Защита от разминаване в данните: проверка на `fs`, `n` и набора ленти спрямо модела.

## Етап 4 — експеримент и документация
Как да се симулират повреди безопасно:
| Повреда | Как |
|---|---|
| Дисбаланс | малко парче тиксо/пластилин на една перка |
| Разхлабено закрепване | освобождаване на един винт/стойка |
| Затруднен въздушен поток | хартия пред решетката |
| Понижено захранване | USB кабел/хъб с пад на напрежението |

Документация: свързване, калибриране, протокол на експеримента, тълкуване на таблото.

|---|---|---|
| 1 | Къде живее монорепото? | Папка `fan-pdm/` в това репо (не в `docs/`, което е за уеб приложенията) |

| 4 | arduinoFFT е GPL-3.0 | Приемливо (фърмуерът става GPL-съвместим) или собствен малък радикс-2 FFT под MIT |
| 5 | Лиценз на проекта | MIT |
| 6 | Wi-Fi настройка | `secrets.h` при компилация (по-късно по избор WiFiManager портал) |
| 7 | MQTT сигурност | Потребител/парола в локалната мрежа, без TLS в първата версия |
| 8 | Модел на ESP32 платката | ESP32 DevKitC (`esp32dev`) |
